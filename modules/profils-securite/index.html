Profils de sécurité et inspection

Choisir le bon profil et distinguer refus réseau, refus applicatif et problème TLS.

Prérequis : Module 3.

01 · Comprendre02 · Approfondir03 · AppliquerRepères GUI / CLIExercice corrigéQuizSources

LEÇON 1 / 3

Attribuer un rôle à chaque contrôle

Antivirus recherche du contenu malveillant ; IPS identifie des signatures d’attaque ; Web Filter traite des catégories et URL ; Application Control identifie des applications. Un service TCP/443 indique un port, pas une application fiable. En mode profile-based, les profils sont associés à une policy : créer un profil sans l’attacher ne protège pas les flux de cette règle.

LEÇON 2 / 3

Comprendre la visibilité

Un contrôle ne peut analyser que ce qu’il voit. Sur un trafic chiffré, l’inspection de certificat et l’inspection approfondie n’offrent pas la même visibilité. L’inspection approfondie déchiffre puis rechiffre ; les postes doivent faire confiance à l’autorité utilisée. Le choix flow/proxy, les licences et les capacités matérielles influencent les fonctions réellement disponibles. Documente ces prérequis avant le test.

LEÇON 3 / 3

Déployer avec preuves

Pars d’une application et d’une règle de test limitées. Observe d’abord les journaux, vérifie le profil effectivement appliqué, puis ajuste le comportement. Une erreur de catégorie, une signature IPS et un certificat non approuvé ne se résolvent pas de la même manière. Une exception doit préciser objet, justification, propriétaire et date de revue ; une désactivation globale détruit la preuve et élargit le risque.

Se repérer dans FortiOS

Dans la GUI

Security Profiles pour créer les profils ; Policy & Objects → Firewall Policy pour les appliquer ; Log & Report pour distinguer trafic et événements de sécurité.

Dans la CLI

show firewall policy
show antivirus profile
show ips sensor
show webfilter profile

Lecture seule. Compare les noms référencés dans la policy à ceux des profils réellement configurés.

Exemple expliqué

Une connexion HTTPS est acceptée au niveau réseau mais un événement Web Filter bloque la catégorie du site. Changer la route ne corrigera pas ce refus de contenu.

À toi de pratiquer

Travaille dans un laboratoire isolé. Si tu n’as pas le matériel requis, rédige les observations attendues ; cela ne remplace pas une validation réelle.

  1. Choisis une application de test interne et consigne son fonctionnement de référence.
  2. Applique un seul profil à la règle de test puis génère un trafic bénin contrôlé.
  3. Relève action, profil, policyid et horaire. Compare avec la référence avant de modifier un second contrôle.
Afficher le corrigé de l’exercice

Un test exploitable associe un événement à la même session et au même instant. « Le site ne marche plus » ne distingue pas réseau, TLS et filtrage ; le journal du moteur donne la catégorie de cause.

Erreur fréquente

Confondre une policy ACCEPT avec la garantie que tous les contrôles de sécurité laisseront passer le contenu.

VÉRIFIER SES ACQUIS

Quiz du module 4

Trois questions, un point par réponse correcte. Tu peux réessayer sans limite. Une réponse non renseignée est signalée séparément ; elle ne rapporte pas de point.

1. Un port 443 prouve-t-il l’identité d’une application ?

2. Créer un profil sans l’appliquer à une règle protège-t-il son trafic ?

3. Quel profil traite les catégories de sites web ?

Consulter le corrigé du quiz

1. Un port 443 prouve-t-il l’identité d’une application ?
Réponse : Non. Un port de transport ne suffit pas à identifier l’application.

2. Créer un profil sans l’appliquer à une règle protège-t-il son trafic ?
Réponse : Non. Le profil doit être associé au flux traité.

3. Quel profil traite les catégories de sites web ?
Réponse : web filter. Le filtrage web traite notamment les catégories et URL.
