MODULE 17 · Production · 60 MIN ESTIMÉES

Accès distant IPsec et authentification

Valider l’accès d’un utilisateur distant sans confondre tunnel, droits et application.

Prérequis : Modules 5, 10 et 15.

01 · Comprendre02 · Approfondir03 · AppliquerRepères GUI / CLIExercice corrigéQuizSources

LEÇON 1 / 3

Choisir selon la version

Dans FortiOS 7.6.3, le mode tunnel SSL VPN est remplacé par IPsec. Ne copie donc pas un guide ancien sans vérifier sa version. Distingue également Agentless VPN du tunnel réseau. Pour préparer l’accès distant, vérifie compatibilité FortiClient/FortiOS, méthode d’authentification, support MFA et contraintes réseau du poste. La version retenue ici est une référence de cours, pas une recommandation de patch de production.

LEÇON 2 / 3

Décrire le trajet distant

Le client doit joindre la passerelle, s’authentifier, négocier puis recevoir les paramètres adaptés. Le réseau de pool VPN ne doit pas chevaucher les réseaux nécessaires. En split tunnel, seules les destinations prévues empruntent le tunnel ; en tunnel complet, d’autres dépendances comme DNS et sortie Internet passent aussi par l’entreprise. Documente le comportement attendu avant de dépanner.

LEÇON 3 / 3

Autoriser au plus juste

Une connexion VPN établie ne donne pas accès à tout le LAN. Les policies doivent limiter groupes, destinations et services. Teste un utilisateur autorisé et un utilisateur hors groupe. Vérifie la résolution interne, le trajet retour et le MFA prévu. Un test positif seul ne démontre pas que les accès non autorisés sont refusés.

Se repérer dans FortiOS

Dans la GUI

VPN → IPsec Tunnels ; User & Authentication pour les groupes et serveurs ; Policy & Objects pour les règles d’accès.

Dans la CLI

get vpn ipsec tunnel summary
diagnose vpn tunnel list
show user group

Lecture seule. Ne publie pas les identités, secrets ou paramètres d’authentification issus des sorties.

Exemple expliqué

Le client affiche « connecté » et reçoit une adresse, mais l’application interne ne résout pas son nom. Il faut vérifier le DNS et les routes annoncées avant de recréer le tunnel.

À toi de pratiquer

Travaille dans un laboratoire isolé. Si tu n’as pas le matériel requis, rédige les observations attendues ; cela ne remplace pas une validation réelle.

  1. Écris une matrice utilisateur/groupe/application/service et le choix split ou full tunnel.
  2. Dans le laboratoire, teste un compte autorisé depuis un réseau externe contrôlé.
  3. Teste le refus d’un compte hors groupe et d’une destination non prévue, puis documente MFA, DNS et chemin retour.
Afficher le corrigé de l’exercice

La validation combine tunnel établi, accès métier réussi et refus attendu hors périmètre. Le voyant connecté du client n’est qu’une étape.

Erreur fréquente

Créer une policy VPN → LAN avec toutes destinations et tous services uniquement pour faire disparaître un incident.

Consulter le corrigé du quiz

1. Quel mode remplace SSL VPN tunnel à partir de FortiOS 7.6.3 ?
Réponse : IPsec VPN. La note de version annonce le remplacement par IPsec.

2. Comment appelle-t-on le mode où seules certaines destinations passent dans le tunnel ?
Réponse : split tunnel. Le split tunnel limite les destinations routées dans le VPN.

3. Quel test complète un accès réussi ?
Réponse : Un refus attendu hors groupe ou hors périmètre. Un contrôle d’accès doit être vérifié dans les deux sens.
