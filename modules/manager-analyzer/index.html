MODULE 19 · Expertise · 60 MIN ESTIMÉES

FortiManager et FortiAnalyzer en exploitation

Préparer une installation centralisée et retrouver une preuve dans les logs.

Prérequis : Modules 8 et 14 ; produits de laboratoire pour les manipulations.

01 · Comprendre02 · Approfondir03 · AppliquerRepères GUI / CLIExercice corrigéQuizSources

LEÇON 1 / 3

Définir la source de vérité

FortiManager maintient des objets et packages de policies pour des cibles de déploiement. Un changement local sur le FortiGate peut diverger de cet état. Avant d’installer, identifie la version de référence et les modifications à conserver. Les ADOM organisent des périmètres administratifs ; ils ne sont pas des VDOM réseau et ne réalisent pas le même type de séparation.

LEÇON 2 / 3

Prévisualiser avant d’installer

Sélectionne explicitement package et équipements cibles, vérifie les mappings d’interfaces et objets propres à chaque site, puis lis l’Install Preview. Le diff attendu doit correspondre au besoin autorisé. Une suppression inattendue est un motif de retour à l’analyse. Une installation terminée doit être suivie de tests métier et de vérification de l’état synchronisé.

LEÇON 3 / 3

Utiliser les journaux centralisés

FortiAnalyzer aide à explorer les événements de plusieurs équipements. Il faut vérifier réception, horodatage, périmètre de collecte et rétention. Filtre par équipement, VDOM, fenêtre temporelle et flux. Un beau rapport vide peut résulter d’un filtre inadéquat ou d’une collecte interrompue. La présence du log récent d’un test connu est une preuve plus directe.

Se repérer dans FortiOS

Dans la GUI

FortiManager : Device Manager et Policy & Objects → Policy Packages → Install Wizard. FortiAnalyzer : Log View et vues d’analyse selon version.

Dans la CLI

show system central-management
show log fortianalyzer setting

À lire sur le FortiGate pour identifier les destinations ; l’état de tâche s’examine sur FortiManager et la réception sur FortiAnalyzer.

Exemple expliqué

Le même package vise deux agences avec des noms d’interfaces différents. Sans mapping correct, le déploiement peut échouer ou ne pas représenter le chemin attendu.

À toi de pratiquer

Travaille dans un laboratoire isolé. Si tu n’as pas le matériel requis, rédige les observations attendues ; cela ne remplace pas une validation réelle.

  1. Crée une modification limitée dans un package de laboratoire destiné à un seul pare-feu.
  2. Lis le diff, vérifie les cibles et installe après validation du changement prévu.
  3. Génère une connexion de test et retrouve son journal centralisé ; compare avec le résultat métier.
Afficher le corrigé de l’exercice

La preuve comprend le diff prévu, la tâche terminée, l’état du pare-feu et un test métier corrélé aux logs. « Install successful » ne suffit pas à valider l’application.

Erreur fréquente

Installer un package sur tous les sites pour gagner du temps avant d’avoir vérifié les mappings et un pilote.

VÉRIFIER SES ACQUIS

Quiz du module 19

Trois questions, un point par réponse correcte. Tu peux réessayer sans limite. Une réponse non renseignée est signalée séparément ; elle ne rapporte pas de point.

1. À quoi sert Install Preview ?

2. Quel domaine administratif organise les périmètres FortiManager ?

3. Un rapport vide prouve-t-il l’absence d’événements ?

Consulter le corrigé du quiz

1. À quoi sert Install Preview ?
Réponse : Vérifier les modifications avant installation. Il permet de confronter le diff au changement prévu.

2. Quel domaine administratif organise les périmètres FortiManager ?
Réponse : adom. Un ADOM est un domaine administratif, distinct d’un VDOM.

3. Un rapport vide prouve-t-il l’absence d’événements ?
Réponse : Non. Collecte, filtres, heure et rétention peuvent expliquer le vide.
