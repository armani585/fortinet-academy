MODULE 13 · Production · 55 MIN ESTIMÉES

FortiClient EMS, posture et ZTNA

Expliquer une décision d’accès combinant utilisateur, terminal et posture.

Prérequis : Modules 10 et 15 conseillé pour les certificats ; EMS et licences adaptés pour la pratique.

01 · Comprendre02 · Approfondir03 · AppliquerRepères GUI / CLIExercice corrigéQuizSources

LEÇON 1 / 3

La posture est une information

EMS reçoit des données des terminaux et applique des règles de tags : appartenance à un domaine, état de sécurité ou autres critères disponibles. FortiGate synchronise ces informations via un connecteur. Un tag attendu mais absent exige de vérifier la règle EMS, le dernier contact du terminal et la synchronisation. L’IP seule ne résume pas l’identité et l’état du terminal.

LEÇON 2 / 3

Comprendre les contrôles possibles

Les tags peuvent participer à des règles de sécurité. Une passerelle applicative ZTNA peut contrôler l’accès à une application avec identité, certificat du terminal et posture. L’utilisation de tags dans une firewall policy n’est pas à elle seule identique à une passerelle ZTNA complète. Les capacités diffèrent selon plateforme, mémoire, version et produit client.

LEÇON 3 / 3

Valider le cycle complet

Vérifie le certificat du serveur EMS, l’autorisation du FortiGate côté EMS et la présence des tags. Teste ensuite un terminal conforme et un terminal volontairement non conforme dans le laboratoire. Mesure le délai de changement observé. Une posture n’est pas nécessairement recalculée instantanément : le cycle de télémétrie et de synchronisation doit être pris en compte.

Se repérer dans FortiOS

Dans la GUI

Security Fabric → Fabric Connectors → FortiClient EMS ; Policy & Objects → ZTNA pour les tags et règles disponibles.

Dans la CLI

show endpoint-control fctems
diagnose firewall dynamic list

Lecture seule. Compare les adresses résolues par les objets dynamiques avec le terminal réellement testé.

Exemple expliqué

Un poste a le bon utilisateur mais manque le tag « conforme ». Autoriser le groupe AD seul contournerait le contrôle de posture prévu ; il faut comprendre pourquoi le tag n’est pas présent.

À toi de pratiquer

Travaille dans un laboratoire isolé. Si tu n’as pas le matériel requis, rédige les observations attendues ; cela ne remplace pas une validation réelle.

  1. Définis une règle de conformité observable dans EMS sur un groupe pilote.
  2. Vérifie sa synchronisation et limite une application de test au groupe et à la posture attendus.
  3. Modifie le critère sur le terminal de laboratoire, observe le résultat puis restaure sa conformité.
Afficher le corrigé de l’exercice

La preuve relie état terminal, tag EMS, objet synchronisé et décision d’accès. Une simple capture d’un tag dans EMS ne prouve pas son utilisation effective par le FortiGate.

Erreur fréquente

Traiter une information de posture ancienne comme une preuve actuelle, ou confondre la confiance TLS avec l’autorisation de l’équipement.

VÉRIFIER SES ACQUIS

Quiz du module 13

Trois questions, un point par réponse correcte. Tu peux réessayer sans limite. Une réponse non renseignée est signalée séparément ; elle ne rapporte pas de point.

1. Un tag présent dans EMS prouve-t-il qu’il est appliqué au flux ?

2. Quel composant produit les tags de posture dans ce parcours ?

3. Identité correcte mais posture non conforme : quel résultat attend une règle exigeant les deux ?

Consulter le corrigé du quiz

1. Un tag présent dans EMS prouve-t-il qu’il est appliqué au flux ?
Réponse : Non, synchronisation et règle restent à vérifier. Il faut suivre toute la chaîne de décision.

2. Quel composant produit les tags de posture dans ce parcours ?
Réponse : ems. EMS calcule les tags à partir des données des terminaux.

3. Identité correcte mais posture non conforme : quel résultat attend une règle exigeant les deux ?
Réponse : Accès refusé. Les deux conditions sont nécessaires dans cette règle.
