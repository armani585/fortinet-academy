MODULE 11 · Avancé · 45 MIN ESTIMÉES

VDOM et séparation des contextes

Diagnostiquer dans le bon domaine et expliquer les échanges entre VDOM.

Prérequis : Modules 3 et 9.

01 · Comprendre02 · Approfondir03 · AppliquerRepères GUI / CLIExercice corrigéQuizSources

LEÇON 1 / 3

Une séparation logique

Les VDOM divisent un FortiGate en contextes disposant de configurations réseau et de sécurité distinctes. Certaines ressources et certains paramètres restent globaux. Le nombre disponible et les fonctions dépendent du modèle et des licences. Une séparation logique n’annule pas les ressources physiques communes ni les risques d’une panne de l’équipement.

LEÇON 2 / 3

Le contexte change la lecture

La même adresse peut exister dans des contextes isolés. Avant de lire une route, une policy ou une session, identifie le VDOM concerné. Un administrateur limité peut ne pas voir les autres domaines. Le domaine de gestion et les services générés par l’équipement doivent être compris séparément des flux de transit.

LEÇON 3 / 3

Relier sans supprimer la séparation

Un lien inter-VDOM crée un chemin entre domaines ; il ne donne pas une autorisation universelle. Chaque côté doit avoir adressage, routes et policies adaptés. Dessine le parcours complet : interface utilisateur, premier domaine, lien inter-VDOM, second domaine puis sortie. Un oubli sur l’un des domaines suffit à bloquer le trajet.

Se repérer dans FortiOS

Dans la GUI

Sélecteur de VDOM, contexte Global et vues propres à chaque VDOM. L’activation multi-VDOM dépend du modèle et doit être préparée.

Dans la CLI

get system status

# Sur un laboratoire où le VDOM LAB existe déjà :
config vdom
    edit LAB
        get router info routing-table all
    end

Remplace LAB par un VDOM existant confirmé. Ne change pas le mode VDOM d’un équipement en production pour suivre cet exercice.

Exemple expliqué

Une route par défaut existe dans root mais pas dans le VDOM des utilisateurs. Elle ne suffit pas à assurer leur sortie Internet.

À toi de pratiquer

Travaille dans un laboratoire isolé. Si tu n’as pas le matériel requis, rédige les observations attendues ; cela ne remplace pas une validation réelle.

  1. Sur un laboratoire déjà configuré en multi-VDOM, relève les interfaces affectées à chaque domaine.
  2. Trace un échange inter-VDOM avec les routes et policies nécessaires des deux côtés.
  3. Consulte la table de routage dans chaque contexte et explique les différences.
Afficher le corrigé de l’exercice

Le flux doit être autorisé sur toutes les portions où une décision de sécurité s’applique. Une route visible dans un domaine ne doit pas être supposée présente dans l’autre.

Erreur fréquente

Lancer un diagnostic dans root alors que le trafic traverse LAB, puis conclure que le FortiGate ne voit aucun paquet.

VÉRIFIER SES ACQUIS

Quiz du module 11

Trois questions, un point par réponse correcte. Tu peux réessayer sans limite. Une réponse non renseignée est signalée séparément ; elle ne rapporte pas de point.

1. Une route de root est-elle automatiquement une route de tous les VDOM ?

2. Quel contexte porte notamment les paramètres communs aux VDOM ?

3. Un lien inter-VDOM remplace-t-il les policies ?

Consulter le corrigé du quiz

1. Une route de root est-elle automatiquement une route de tous les VDOM ?
Réponse : Non. Chaque contexte possède sa configuration de routage.

2. Quel contexte porte notamment les paramètres communs aux VDOM ?
Réponse : global. Les paramètres communs sont gérés dans le contexte Global.

3. Un lien inter-VDOM remplace-t-il les policies ?
Réponse : Non. Il crée une connectivité, pas une autorisation générale.
