LAB 01 · 60 MIN ESTIMÉES

Construire un premier flux LAN → DMZ

Autoriser uniquement un poste à joindre HTTPS sur un serveur de laboratoire.

Préparer le travail

Un FortiGate physique ou VM licencié pour les fonctions utilisées, accès console, deux réseaux isolés et deux hôtes. port2 relie le poste 10.10.10.10/24 ; port3 relie le serveur 10.10.20.10/24, avec un service HTTPS déjà fonctionnel. Les passerelles des hôtes seront respectivement 10.10.10.1 et 10.10.20.1. Adapte les noms de ports existants ; ils doivent être libres et ne pas appartenir à un switch logiciel ou matériel. Ne débranche pas le port de gestion.

Cours associés

  • Module 1 — Comprendre FortiGate et le chemin d’un flux
  • Module 2 — Interfaces, VLAN et adressage
  • Module 3 — Policies, SNAT et publication par VIP

Le dossier

État initial attendu : les deux hôtes fonctionnent dans leur segment, mais aucun accès LAN → DMZ n’est autorisé. Les adresses et ports indiqués sont des paramètres de laboratoire, pas ceux de ton réseau réel.

Manipulation ou analyse guidée

  1. Sauvegarde la configuration et vérifie l’accès console. Vérifie aussi le service HTTPS localement côté serveur.
  2. Configure les interfaces et objets avec l’exemple ci-dessous, puis règle les passerelles des hôtes.
  3. Place la règle de test avant toute règle qui pourrait la masquer et vérifie qu’aucune autre règle large n’autorise déjà le trajet.
  4. Teste HTTPS depuis 10.10.10.10, puis teste un autre service non autorisé. Examine les logs et le policyid.
  5. À la fin, restaure la sauvegarde du laboratoire ou retire uniquement les objets créés, après leurs références.

Configuration d’exemple — laboratoire uniquement

config system interface
    edit "port2"
        set ip 10.10.10.1 255.255.255.0
        set allowaccess ping
    next
    edit "port3"
        set ip 10.10.20.1 255.255.255.0
        set allowaccess ping
    next
end
config firewall address
    edit "LAB-PC"
        set subnet 10.10.10.10 255.255.255.255
    next
    edit "LAB-WEB"
        set subnet 10.10.20.10 255.255.255.255
    next
end
config firewall policy
    edit 0
        set name "LAB-PC-HTTPS-DMZ"
        set srcintf "port2"
        set dstintf "port3"
        set srcaddr "LAB-PC"
        set dstaddr "LAB-WEB"
        set action accept
        set schedule "always"
        set service "HTTPS"
        set nat disable
        set logtraffic all
    next
end

Les commandes et observations sont pédagogiques. Vérifie la syntaxe disponible avec l’aide CLI de ta version. Aucune commande n’est exécutée depuis cette page.

Rendre ton diagnostic

Rédige les adresses source/destination vues dans chaque segment et explique pourquoi aucun SNAT n’est nécessaire ici.

Afficher le corrigé du lab

Le serveur voit la source 10.10.10.10, car les deux LAN sont routés et le serveur renvoie via 10.10.20.1. La policy autorise uniquement HTTPS du poste prévu vers le serveur prévu. Une règle de retour pour une nouvelle connexion serveur → poste n’est pas ajoutée : ce besoin n’existe pas dans le scénario.

Critères de réussite

  • HTTPS réussit pour le poste de test et le journal identifie LAB-PC-HTTPS-DMZ.
  • Un service différent est refusé en l’absence d’autre règle qui l’autorise.
  • Le serveur possède le chemin retour ; les paramètres de gestion sont restés accessibles.

Retour à l’état initial

Restaure la sauvegarde initiale du laboratoire si tu n’as pas besoin de conserver le montage. Une restauration peut redémarrer l’équipement : garde la console.
